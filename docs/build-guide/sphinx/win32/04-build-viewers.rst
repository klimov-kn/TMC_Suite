============================================================================
win32 · Шаг 4. Фаза 2 — сборка вьюверов (3 программы)
============================================================================

На этом шаге собираются три программы-вьювера под 32 бита. Все они — MFC-приложения
(статическая MFC, набор символов MultiByte) и линкуются с библиотеками **sfile95**,
**complex**, **exprint**.

.. note::

   Перед сборкой Фазы 2 убедитесь, что **все 6 библиотек** из Фазы 1 лежат в
   ``dist\win32\lib`` (см. ``03-build-libs``, раздел 3.8).

.. note::

   Перед сборкой: конфигурация **Release**, платформа **Win32**.

----

4.0 Что уже сделано в проектах вьюверов
=======================================

**Правки настроек сборки (``.vcxproj``/``.sln``), не код:**

- Старые ``.vcproj`` (формат VS2008) заменены на новые ``.vcxproj`` (toolset **v145**).
- Подключён ``build\ExeOutput.props`` (вывод ``.exe`` в ``dist\<платформа>\bin``).
- Убраны жёсткие пути ``D:\work``, ``c:\tmc``.

**Правка runtime-бага вьюверов (Баг #5)** — уже внесена в код. Без неё все три вьювера
при запуске показывали ошибку MFC «Encountered an improper argument». Подробности —
в ``07-troubleshooting``. Кратко, что изменено в коде каждого вьювера:

- в ``MakeDocFileName`` вызовы ``SetPathName(...)`` дополнены вторым аргументом ``FALSE``
  (``SetPathName(GetTitle(), FALSE)`` и ``SetPathName(ch1, FALSE)``);
- в ``InitInstance`` добавлены ``AfxOleInit();`` и ``SetRegistryKey("<имя_программы>")``;
- в ``StdAfx.h`` добавлен ``#include <afxdisp.h>``.

Эти правки **не зависят от разрядности** (нужны и для win32, и для win64).

4.1 Общая последовательность для каждого вьювера
================================================

1. **File → Open → Project/Solution…** и выбрать файл проекта **``.vcxproj``** вьювера
   из его папки (точное имя — в разделах 4.2–4.4 ниже).

   .. warning::

      ⚠️ **НЕ открывайте ``TMCGROUT.SLN``.** В папке каждого вьювера лежит старое решение
      ``TMCGROUT.SLN`` (формат VS2008), и оно ссылается на **устаревший
      ``TMCGROUT.vcproj``** с жёсткими путями. Если открыть ``.SLN``, вы увидите проект
      «TMCGROUT» (а не TMCROS/TMC_DN) и соберёте старый проект. Новые, уже настроенные
      проекты названы по-разному: ``TMCROS.vcxproj``, ``TMCGROUT.vcxproj``,
      ``TMC_DN.vcxproj`` — открывайте именно их.

2. Проверить: конфигурация **Release**, платформа **Win32**.
3. Проверить, что в линковке указаны библиотеки (см. ниже).
4. **Build → Build Solution** (или **Rebuild Solution** для чистой сборки).
5. Дождаться ``Build: succeeded``.
6. Убедиться, что ``.exe`` появился в ``dist\win32\bin``.

Как проверить список библиотек линковки
---------------------------------------

Правой кнопкой по проекту → **Properties** → **Linker → Input → Additional
Dependencies** (Компоновщик → Ввод → Дополнительные зависимости). Должны быть
перечислены::

   sfile95.lib
   complex.lib
   exprint.lib

4.4 TMC_DN.exe — вьювер диаграмм направленностей
================================================

   заголовок). Никаких дополнительных действий не требуется.

4.5 Проверка Фазы 2
===================

Откройте ``<КОРЕНЬ>\dist\win32\bin``. Должны лежать три файла::

   TMCROS.exe
   TMCGROUT.exe
   TMC_DN.exe

Запустите каждый — должно открыться окно программы **без** ошибки «Encountered an
improper argument». Для проверки открытия файла используйте тестовые данные из
``samples\SAMPLE_R`` (например, ``horns.soc``).

Если всё в порядке — переходите к **``05-build-kernels``** (Фаза 3 — ядра).
