========================
Граф знаний (graphify)
========================

Этот раздел описывает **граф связей** пакета TMC Suite, построенный инструментом
**graphify**. Граф — машинно- и человекочитаемая карта связей между файлами, классами
и функциями проекта. Он публикуется вместе с исходниками: посетитель может визуально
изучить структуру пакета, искать по ней и переиспользовать данные в собственных
инструментах.

1. Зачем это в архитектуре
==========================

Обычная документация (API, сборка, руководство пользователя) описывает компоненты
**по отдельности**. Граф показывает пакет как **единую сеть связей**: какие модули
ссылаются друг на друга, какие функции вызываются вместе, какие части кода образуют
связную группу. Это даёт три практических эффекта:

- **Навигация по смыслу.** Можно начать с любого узла и пройти по связям к смежным
  частям, не зная заранее имён файлов.
- **Поиск внутри.** Граф включает поисковый индекс — по слову находятся связанные узлы.
- **Переиспользование.** Данные выгружены в открытом формате (``graph.json``), пригодном
  для сторонних инструментов и GraphRAG-конвейеров.

2. Что входит в граф
====================

Граф строится **по исходному коду** — C++/MFC/OpenGL, заголовки и файлы проектов Visual
Studio из каталога ``src/``. Документация в граф не включена: она описана обычными
средствами и её индексация только размывала бы картину связей кода.

Текущие показатели сборки:

.. list-table::
   :header-rows: 1
   :widths: 55 45

   * - Показатель
     - Значение
   * - Узлы (файлы, классы, функции)
     - **4649**
   * - Связи (включения, вызовы, наследование)
     - **9271**
   * - Группы (сообщества)
     - **333**
   * - Источник
     - 489 файлов · ~453 000 слов
   * - Достоверность связей
     - 98 % извлечено напрямую (EXTRACTED), 2 % выведено (INFERRED, 168 связей,
       средняя уверенность 0,8)

Узлы автоматически группируются в **сообщества** — кластеры плотно связанных между собой
элементов. Сообщества пронумерованы (``Community 0``, ``Community 1``, …); присвоение им
осмысленных названий — отдельный необязательный этап, требующий языковой модели, и он
не выполнялся. Внутри сообществ выделяются **узлы-концентраторы** (god nodes) — точки,
через которые проходит больше всего связей; они служат удобными «входами» при навигации.

3. Артефакты
============

Файлы графа лежат в каталоге ``graphify-out/`` в корне репозитория:

.. list-table::
   :header-rows: 1
   :widths: 28 72

   * - Файл
     - Назначение
   * - ``graph.html``
     - Интерактивный граф — открывается двойным щелчком в браузере, узлы кликабельны,
       есть поиск. Отдельная установка не нужна
   * - ``graph.json``
     - Данные графа в открытом формате — для переиспользования сторонними инструментами
   * - ``GRAPH_REPORT.md``
     - Аудит-отчёт: сводка, концентраторы, состав сообществ
   * - ``.graphify_labels.json``
     - Названия сообществ (служебный)

4. Как граф поддерживается в актуальном состоянии
=================================================

Обновление идёт по синтаксическому разбору (AST) и **не обращается к платным сервисам**.
После правок в коде граф пересобирается одной командой — она же перезаписывает
``graph.html`` и ``GRAPH_REPORT.md``:

.. code-block:: bash

   graphify update .

Запросы к уже построенному графу (без пересборки):

.. code-block:: bash

   graphify query "Как данные ядра попадают во вьювер?"   # обзорный ответ по графу
   graphify path "PlanarRT_H" "FieldView"                 # кратчайший путь между узлами
   graphify explain "Чтение S-матриц"                     # пояснение одного узла

5. Статус и назначение
======================

Граф знаний — **дополнительный, справочный** слой документации. Он не входит в собранные
программы и не влияет на расчёты; это инструмент навигации и переиспользования.
Публикуется открыто вместе с остальной архитектурной документацией, чтобы внешние
разработчики и исследователи могли изучать структуру пакета, не разбирая исходники с нуля.
